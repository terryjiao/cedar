# 下一里程碑 DSH 单任务执行

状态：待开始。当前 v0.1.0 只做静态接入，没有可用的 DSH 执行适配器。下一里程碑要让覆盖图中的一个任务成为真实运行、有证据、有明确结果的实验。

本文件确定范围与验收条件。具体 DSH 调用入口、接口和代码拆分，需要在运行时核查后形成实现计划；这里不假定已有可用 API。

## 先验证运行时一致性

确认所用 DSH 版本、启动方式、profile、插件组合、工具、输入上下文和持久状态。检查自动化入口与实际产品使用方式的差异，以及任务结束、后台工作和输出产物如何识别。

完成条件：通过一次最小运行探针，给出自动化入口能够保留的行为、缺失能力和执行证据。如果某些产品能力无法通过该入口运行，保留明确阻塞，不把简化后的替代流程当作完整产品评测。

## 建立最小任务与运行记录

从覆盖图中选择一个有代表性且结果可核验的任务。优先复用项目已有案例或合成输入，由宿主 agent 起草任务定义，开发者确认关键业务预期。

任务需要包含：

- 用户目标、输入与所需初始状态。
- 目标版本和有效运行配置的引用。
- 预期输出、判定方式与不能自动判断的部分。
- 执行所需条件、时间边界和阻塞。

运行记录需要保存输入与任务版本、实际配置、开始与结束状态、可获得的执行轨迹、输出产物，以及判定所用证据。凭证不应写入任务包或报告。

先完成一条可复用的数据流。无需提前建立完整数据集管理平台，也不要求用户手写全部任务 JSON。

## 在独立状态中执行和判断

目标任务在独立工作目录或经验证的隔离状态中运行，能重建文件、记忆和其他影响结果的初始状态。接入采集流程继续保持只读；执行流程需要单独定义允许的工具和副作用边界。

任务结果与执行故障分别记录。输出可以判断为通过、失败或待人工审阅；启动失败、超时、缺少输入等情况要保留具体原因，不能当作已完成评测。第一次可以采用确定性检查或人工判定，不要求先实现通用模型裁判。

## 里程碑验收

- [ ] DSH 自动化入口和实际产品行为的一致性有可检查证据。
- [ ] 一个完整任务能从输入运行到产物收集和结果判断。
- [ ] 可以重建同样的初始条件重复运行，并保留各次结果；不要求随机模型输出完全相同。
- [ ] 隔离与重置有验证证据，不污染原项目或日常使用状态。
- [ ] 成功、行为失败、运行故障和待审阅状态可以区分。
- [ ] 结果可追溯到任务、目标版本、配置、输出和判定依据。
- [ ] 同一条核心流程不包含客户名称或领域专属分支。

## 接下来才做最小 A/B

单任务运行可信后，对相同任务、初始条件和判定标准分别运行 baseline 与 candidate，展示结果、行为差异和运行故障。记录重复次数和模型波动；单次胜出不能直接推出稳定改进。

本里程碑不包含自动修复、多运行时、托管 SaaS 或完整自主改进循环。更长阶段见 [路线图](roadmap.md)。
